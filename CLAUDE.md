# pdd-swipe

PWA-тренажёр теоретического экзамена ГИБДД (категории A/B): ответ выбирается свайпом,
чтобы к вопросу привязывалась моторная память. Основное устройство — iPhone, приложение
ставится на экран «Домой». Полная спецификация и все принятые решения:

@docs/SPEC.md

## Стек
- Vite + TypeScript (strict), без UI-фреймворка
- Жесты — Pointer Events, анимации — CSS transitions
- vite-plugin-pwa: precache всего (оболочка, questions.json, картинки)
- IndexedDB через idb-keyval; планировщик повторений — ts-fsrs
- Тесты — vitest
- Подготовка данных — Python 3, только стандартная библиотека
- Деплой — GitHub Pages через GitHub Actions

## Команды
- `python3 scripts/build_data.py` — скачать датасет в .cache/ и собрать public/data/
- `npm run dev` — дев-сервер; `npm run dev -- --host` — открыть с телефона по Wi-Fi
- `npm test` — юнит-тесты
- `npm run build` — продакшен-сборка в dist/
(npm-команды появляются на этапе 2)

## Правила
- Со мной общайся по-русски; идентификаторы, комментарии в коде и коммиты — по-английски
- Раскладку свайпов не меняй без моего решения: ↑ первый, ↓ последний, ← второй,
  → третий (только при 4 вариантах); тап по карточке = «не знаю»; 5 вариантов — тап по строке
- Чистая логика (раскладка, распознавание жеста, оценка, правила экзамена) живёт в src/core/
  без обращения к DOM и покрыта тестами
- public/data/ и .cache/ — в .gitignore: данные генерирует скрипт, в CI он запускается перед сборкой
- Один этап из SPEC.md — одно рабочее состояние и один коммит; следующий этап сам не начинай
- Прежде чем сказать «готово»: `npm test` и `npm run build` проходят без ошибок
- Новые зависимости сверх стека — только после вопроса
- Если решение из SPEC.md приходится менять — сначала предложи правку SPEC.md
- Любой UI сверяй с разделом «iOS» в SPEC.md
- base в конфиге Vite, scope и start_url манифеста — '/pdd-swipe/' (имя репозитория)
